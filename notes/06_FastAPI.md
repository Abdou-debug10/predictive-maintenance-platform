# FastAPI

Purpose:

FastAPI is the backend framework used in the project.

Role in Architecture:

React Dashboard
       ↓
FastAPI
       ↓
Machine Learning Model
       ↓
Prediction

Responsibilities:

1. Receive requests from frontend.
2. Load trained ML model.
3. Generate predictions.
4. Return results as JSON.

Why FastAPI?

- High performance
- Easy API development
- Automatic API documentation
- Industry adoption in AI/ML systems

Future APIs:

GET /health
POST /predict
GET /machines
GET /predictions

## First Prediction API

Endpoint:

POST /predict

Purpose:

Generate machine failure predictions using the trained XGBoost model.

Workflow:

Client
   ↓
FastAPI
   ↓
Load Saved Model
   ↓
Predict
   ↓
JSON Response

Example Response:

{
    "prediction": "Machine Healthy"
}

Benefits:

- Model served through REST API.
- Can be consumed by React frontend.
- Can be used by external systems.
- Forms the foundation of the Predictive Maintenance Platform.


## Pydantic Request Model

File:

api/models/prediction_request.py

Class:

PredictionRequest

Purpose:

Validate incoming API request data.

Benefits:

1. Automatic validation.
2. Prevents invalid inputs.
3. Generates Swagger documentation automatically.
4. Improves API reliability.

Fields:

- Type
- air_temp
- process_temp
- rotational_speed
- torque
- tool_wear


Dynamic Prediction API

Endpoint:

POST /predict

Input:

Type
air_temp
process_temp
rotational_speed
torque
tool_wear

Output:

Machine Healthy
or
Machine Failure Predicted

Improvement:

The API no longer uses hardcoded sensor values.

Predictions are generated from user-provided machine data.

Benefits:

1. Real-time predictions.
2. Frontend integration ready.
3. IoT sensor integration ready.
4. Production-style API design.
